Arquitectura de Datos Robusta para E-commerce

Google Cloud Platform | BigQuery | Cloud Functions | Data Lake

Contexto del Proyecto

Una multinacional de e-commerce procesa 500GB de transacciones diarias en formato JSON. El sistema actual es manual y propenso a errores. Necesitan una arquitectura robusta que resuelva una variedad de problemas relacionados con la ingesta de datos, limpieza, seguridad, costos y automatización.

Desafíos a Resolver

Ingesta Distribuida

Los archivos llegan de distintas regiones y deben aterrizar en un "Landing Zone" seguro de forma constante.

Validación y Limpieza (ETL)

Los datos vienen "sucios" (fechas en formatos distintos, campos nulos). Se deben limpiar antes de analizarlos.

Gobernanza de Datos (PII)

Los números de tarjeta y correos deben ser enmascarados para cumplir con leyes de privacidad (GDPR).

Arquitectura de Capas

Separar datos en Bronze (crudos), Silver (limpios) y Gold (listos para negocio) siguiendo la arquitectura Medallion.

Optimización de Costos

Los datos "Bronze" de más de 30 días deben pasar automáticamente a almacenamiento de archivo (Coldline).

Automatización

Todo el proceso debe dispararse automáticamente cuando un archivo llega al bucket.

Resolución Técnica con gcloud CLI

Uso de Cloud Functions para la lógica de limpieza (Python) y BigQuery para el análisis. Todo el despliegue de la infraestructura se realiza mediante comandos automatizables de Google Cloud CLI y utilidades como gsutil y bq.

  • 1. Infraestructura de Almacenamiento (Lifecycle Management)

    Primero, creamos el "Landing Zone" y configuramos una política para que los archivos se muevan a almacenamiento barato automáticamente tras 30 días.

    # Crear el archivo de política de ciclo de vida
echo '{
  "rule": [
    {
      "action": {"type": "SetStorageClass", "storageClass": "COLDLINE"},
      "condition": {"age": 30}
    }
  ]
}' > lifecycle.json

# Crear el bucket principal
gsutil mb -l us-east1 gs://global-shop-data-lake/

# Aplicar la política de costos
gsutil lifecycle set lifecycle.json gs://global-shop-data-lake/

  • 2. Capas de Organización (Estructura de Directorios)

    Separamos por país y por estado del dato dentro del mismo bucket implementando una estructura Medallion.

    # Estructura Medallion
gsutil cp /dev/null gs://global-shop-data-lake/bronze/espana/
gsutil cp /dev/null gs://global-shop-data-lake/bronze/mexico/
gsutil cp /dev/null gs://global-shop-data-lake/silver/processed-data/

  • 3. Almacén de Datos Optimizado (BigQuery Partitioning)

    En BigQuery, crear una tabla particionada por fecha. Esto reduce drásticamente los costos de consulta al no tener que leer toda la base de datos cada vez.

    # Crear el Dataset
bq mk --location=us analytics_gold

# Crear tabla particionada por el campo 'fecha_venta'
bq mk --table \
  --schema id:STRING,pais:STRING,monto:FLOAT,fecha_venta:DATE,sku:STRING \
  --time_partitioning_field fecha_venta \
  --time_partitioning_type DAY \
  analytics_gold.ventas_consolidadas

  • 4. Seguridad de Grano Fino (IAM)

    Configurar una Service Account con el principio de "menor privilegio". Solo podrá escribir en el bucket de "Silver" y cargar datos en BigQuery.

    # Crear la identidad del sistema
gcloud iam service-accounts create pipeline-processor-sa \
    --display-name="Procesador Automático de Datos"

# Asignar permisos de visualización en Bronze y escritura en Silver
gsutil iam ch serviceAccount:pipeline-processor-sa@mi-proyecto.iam.gserviceaccount.com:objectViewer gs://global-shop-data-lake/bronze/
gsutil iam ch serviceAccount:pipeline-processor-sa@mi-proyecto.iam.gserviceaccount.com:objectAdmin gs://global-shop-data-lake/silver/

# Asignar permiso para insertar datos en BigQuery
gcloud projects add-iam-policy-binding mi-proyecto-id \
    --member="serviceAccount:pipeline-processor-sa@mi-proyecto-id.iam.gserviceaccount.com" \
    --role="roles/bigquery.dataEditor"

  • 5. El Disparador (Cloud Functions)

    El despliegue se hace por CLI. Esto hace que cada vez que se suba un JSON a /bronze/, la función se ejecute.

    gcloud functions deploy procesar-ventas \
  --runtime python311 \
  --trigger-resource gs://global-shop-data-lake/ \
  --trigger-event google.storage.object.finalize \
  --entry-point main \
  --service-account pipeline-processor-sa@mi-proyecto.iam.gserviceaccount.com
